# Adaptive Context Budget Development Guide / 开发说明

## Document scope / 文档范围

This document explains the implementation logic, persistence boundaries, recovery flow, model-switching constraints, API/TUI propagation, and test structure of the Adaptive Context Budget MVP introduced by commit `045a3465c4`.

本文说明提交 `045a3465c4` 中 Adaptive Context Budget MVP 的实现逻辑、持久化边界、恢复流程、模型切换约束、API/TUI 传播和测试结构。

The feature builds on Codex's existing compaction pipeline; it does not reimplement Responses API compaction.

该功能建立在 Codex 原有 compaction 链路之上，没有重新实现 Responses API compaction。

## Goal / 目标

Previously, Codex used a fixed automatic-compaction threshold from model metadata or configuration. The MVP adds a thread-level Governor:

原有 Codex 使用模型信息或配置中的固定自动压缩阈值。MVP 增加一个线程级 Governor：

```text
272K → 487K → 872K
```

The Governor decides whether to expand according to the complete context usage that remains after each successful automatic context-limit compaction.

Governor 根据每次成功自动上下文压缩后的完整占用决定是否升档。

Core principles:

核心原则：

- The soft budget only controls when automatic compaction happens.
  软预算只决定自动 compaction 时机。
- The model's hard window continues to govern token accounting, input truncation, and safety limits.
  模型硬窗口继续负责 token accounting、输入裁剪和安全限制。
- Model catalog limits are never bypassed.
  不突破模型 catalog 限制。
- The policy is pinned to the thread.
  策略随线程固定。
- Resume and fork use the checkpoint that remains valid after rollback.
  resume 和 fork 使用 rollback 后仍有效的 checkpoint。
- The Governor only moves upward; it does not move down automatically.
  只升档，不降档。

## Key concepts / 关键概念

### Rollout

A rollout is a chronological, persistent log of thread items. It stores the important boundaries needed to replay a thread rather than directly serializing the entire in-memory process.

Rollout 是按时间顺序持久化的线程 item 日志。它保存可以重放线程的重要边界，而不是直接序列化整个进程内存。

Relevant items include:

相关 item 包括：

```text
SessionMeta
ResponseItem
CompactedItem
TurnContext
WorldState
EventMsg
```

### `SessionMeta`

`SessionMeta` is thread-level metadata persisted when a thread is created. The MVP adds an optional initial Adaptive Context Budget checkpoint to it.

`SessionMeta` 是线程创建时持久化的线程级元数据。MVP 在其中增加可选的初始 Adaptive Context Budget checkpoint。

### `SessionState`

`SessionState` is the active thread's in-memory state protected by the Session mutex. The MVP stores `AdaptiveContextBudgetRuntime` in it.

`SessionState` 是活动线程的内存状态，受 Session mutex 保护。MVP 在其中保存 `AdaptiveContextBudgetRuntime`。

`SessionMeta` and `SessionState` belong to different layers:

`SessionMeta` 与 `SessionState` 不是同一层：

```text
SessionMeta  = persisted initial thread record / 持久化的线程初始档案
SessionState = mutable state in the current process / 当前进程中的可变运行状态
Rollout      = replayable thread-change log / 可重放的线程变化记录
```

### `ContextManager`

`ContextManager` holds the current model-visible history, token usage, reference context, and world-state baseline.

`ContextManager` 持有当前模型可见历史、token usage、reference context 和 world-state baseline。

After a successful compaction, `replacement_history` replaces the old history as a whole.

成功 compaction 后，旧历史会被 `replacement_history` 整体替换。

### Three easily confused compaction items / 三种容易混淆的 compaction item

#### Responses API `type=compaction`

This item is generated by `/responses/compact` or Remote Compaction V2 and may contain opaque `encrypted_content`. It is a `ResponseItem` in the model context.

由 `/responses/compact` 或 Remote Compaction V2 生成，可能包含 opaque `encrypted_content`。它是模型上下文中的 `ResponseItem`。

#### Rollout `CompactedItem`

This is the Codex host's persisted checkpoint for installing compacted history. It contains replacement history, window metadata, and the Adaptive Context Budget checkpoint.

Codex host 持久化的压缩安装 checkpoint，包含 replacement history、window metadata 和 Adaptive Context Budget checkpoint。

#### UI `ContextCompactionItem`

This item displays the compaction started/completed lifecycle in app-server and TUI. It does not persist Governor state.

用于 app-server/TUI 展示 compaction started/completed 生命周期，不承担 Governor 持久化。

## Soft budget and hard window / 软预算与硬窗口

The current soft budget is:

当前软预算：

```text
B = target_context_budget_tokens
```

The automatic-compaction threshold is:

自动压缩阈值：

```text
effective_compact_limit =
    min(floor(0.9 × B), catalog_auto_compact_limit)
```

The runtime hard window is resolved by:

运行时硬窗口：

1. Prefer an explicit `model_context_window` after the existing catalog clamp.
   优先使用经过现有 catalog clamp 的显式 `model_context_window`。
2. Otherwise use catalog `max_context_window`.
   否则使用 catalog `max_context_window`。
3. If missing, fall back to the resolved context window.
   缺失时退回 resolved context window。
4. Continue applying the model's existing effective-context percentage to obtain its usable hard window.
   继续应用模型现有 effective-context percentage 得到模型可用硬窗口。

`context_window_token_status` compares both:

`context_window_token_status` 同时比较：

- Whether the current context has reached the Governor's soft compaction threshold.
  当前上下文是否达到 Governor 软压缩线。
- Whether the current context has reached the model's hard window.
  当前上下文是否达到模型硬窗口。

Therefore, the soft budget is never incorrectly used for input truncation or model safety checks.

因此软预算不会被错误用于输入裁剪或模型安全判断。

## Compaction feedback state machine / 压缩反馈状态机

After the replacement history is successfully installed, Codex re-estimates the complete context:

成功安装 replacement history 后，重新估算完整上下文：

```text
U_after = estimated tokens of replacement history + base instructions
```

The comparison uses `i128` integer cross-multiplication to avoid floating-point boundary errors.

比较使用 `i128` 整数交叉相乘，避免浮点边界误差。

### Low range / 低区

```text
U_after × 100 < keep × B
```

Behavior:

行为：

- Keep the current tier.
  保持当前档位。
- Set `ambiguous_compaction_count = 0`.
  `ambiguous_compaction_count = 0`。

### High range / 高区

```text
U_after × 100 >= expand × B
```

Behavior:

行为：

- Attempt to move to the next tier.
  尝试升入下一档。
- Set `ambiguous_compaction_count = 0`.
  `ambiguous_compaction_count = 0`。

### Middle range / 中间区

```text
keep × B <= U_after × 100 < expand × B
```

Behavior:

行为：

- Increment `ambiguous_compaction_count`.
  累加 `ambiguous_compaction_count`。
- Attempt to expand after the configured count is reached.
  达到策略次数后尝试升档。
- Reset the counter after the attempt.
  尝试后清零。

With default 45/65 thresholds and compaction triggered at approximately 90% of the soft budget, the policy can be approximated as:

默认 45/65 在压缩大约于 90% 软预算触发时，可近似解释为：

```text
Retain less than 50% of pre-compaction usage: keep
压缩后保留不足压缩前的 50%：保持

Retain approximately 50%–72.2%: observe
保留约 50%～72.2%：观察

Retain at least approximately 72.2%: immediately attempt to expand
保留至少约 72.2%：立即尝试升档
```

### Expansion constraints / 升档约束

Expansion must satisfy:

升档必须满足：

1. A next tier exists; otherwise record `max_tier`.
   存在下一档，否则记录 `max_tier`。
2. The candidate tier does not exceed the model's runtime maximum window; otherwise record `model_window_capped`.
   候选档位不超过模型运行时最大窗口，否则记录 `model_window_capped`。
3. The candidate tier's effective compact limit is greater than the current tier's limit; otherwise record `catalog_capped`.
   候选档位的实际 compact limit 高于当前档，否则记录 `catalog_capped`。

Future tiers are not removed during policy normalization.

未来档位不会在策略规范化时被删除。

## Atomic order of a successful compaction / 成功 compaction 的原子顺序

The key part of the old flow was:

旧流程的关键部分是：

```text
replace in-memory history
替换内存历史
→ persist CompactedItem
→ 持久化 CompactedItem
→ recompute_token_usage
→ TokenCount
```

The Governor must obtain `U_after` before persisting the latest checkpoint, so the new flow is:

Governor 必须先获得 `U_after`，再持久化最新 checkpoint，因此新流程为：

```text
1. Assign missing item IDs in replacement history
   为 replacement history 分配缺失的 item ID
2. Replace ContextManager history in SessionState
   替换 SessionState 中的 ContextManager 历史
3. Recompute U_after without emitting TokenCount
   重算 U_after，但不发送 TokenCount
4. Apply Governor feedback for Auto + ContextLimit
   对 Auto + ContextLimit 应用 Governor feedback
5. Obtain the latest AdaptiveContextBudgetCheckpoint
   获取最新 AdaptiveContextBudgetCheckpoint
6. Construct CompactedItem
   构造 CompactedItem
7. Persist CompactedItem
   持久化 CompactedItem
8. Persist WorldState / TurnContext baselines
   持久化 WorldState / TurnContext baseline
9. Emit one TokenCount containing the latest soft budget
   发送一次包含最新软预算的 TokenCount
10. Emit lifecycle completed on the compaction path
    compaction 路径发送 lifecycle completed
```

This avoids emitting an old soft tier followed by a new soft tier.

这样不会先发旧软档位，再发新软档位。

## Resume, rollback, and checkpoint reconstruction / Resume、rollback 与 checkpoint 重建

The implementation cannot simply read the last checkpoint in the rollout because that checkpoint may belong to a turn removed by rollback.

不能简单读取 rollout 中最后一个 checkpoint，因为它可能属于已被 rollback 的 turn。

Reconstruction scans backward:

重建逻辑从尾部逆向扫描：

```text
partition replay segments by TurnStarted / TurnComplete / TurnAborted
按 TurnStarted / TurnComplete / TurnAborted 划分 replay segment
  ↓
identify UserMessage and other real turn boundaries
识别 UserMessage 和其他真实 turn boundary
  ↓
accumulate ThreadRolledBack.num_turns
累计 ThreadRolledBack.num_turns
  ↓
discard rolled-back segments
丢弃被 rollback 的 segment
  ↓
collect checkpoints from CompactedItems that remain valid
收集仍有效的 CompactedItem checkpoint
```

Recovery priority:

恢复优先级：

1. The latest `CompactedItem` checkpoint that remains valid.
   最新仍有效的 `CompactedItem` checkpoint。
2. The initial `SessionMeta` checkpoint.
   `SessionMeta` 初始 checkpoint。

Reconstruction also detects:

重建同时检测：

- Unknown policy versions.
  未知 policy version。
- Policy/state version mismatches.
  policy/state version 不一致。
- Invalid tiers or counters.
  无效档位或 count。
- Policy drift within one thread.
  同一线程内 policy 漂移。

Errors are stored in the Runtime. Reading the thread remains allowed, but the sampling entry point returns an explicit error.

错误保存在 Runtime 中，读取线程仍然允许，采样入口返回明确错误。

## `AutoCompactWindow` recovery / `AutoCompactWindow` 恢复

Adaptive Context Budget and the existing `AutoCompactWindow` are two parallel state systems.

Adaptive Context Budget 与既有 `AutoCompactWindow` 是两套并行状态。

Governor checkpoint 恢复当前软预算；AutoCompactWindow 恢复上下文窗口身份和计数。二者不可混用。

## Model switching / 模型切换

Before updating Session settings, the implementation resolves the candidate model metadata and validates the following in the commit path while holding the `SessionState` lock:

Session settings 更新前先解析候选模型 metadata，并在持有 SessionState lock 的提交路径中校验：

```text
current target soft budget <= candidate runtime maximum
```

If incompatible, it returns a `ConstraintError` before any settings or runtime side effect occurs, so the rejection is atomic.

不兼容时，在任何设置或运行时副作用发生前返回 ConstraintError，因此拒绝是原子的。

Only the current target tier is checked. Future policy tiers above the candidate model's capability do not block switching.

只检查当前目标档位；未来策略档位超过候选模型能力不阻止切换。

Every normal sampling entry point validates compatibility again. This covers resuming onto an incompatible model. Switching to a compatible model removes the block without modifying the checkpoint.

每次正常采样入口还会再次校验，用于处理 resume 到不兼容模型的情况。切换到兼容模型后，无需修改 checkpoint 即可解除阻塞。
